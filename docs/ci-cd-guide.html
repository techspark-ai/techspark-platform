📋 Overview

TechSpark AI Platform uses GitHub Actions for continuous integration and deployment. Our CI/CD pipeline ensures code quality, security, and reliable deployments.

ℹ️ Info: All workflows run automatically on push to main or pull requests.

Pipeline Architecture

Push to GitHub
    ↓
Lint & Test Workflow
    ├─ ESLint
                        ├─ TypeScript Check
    ├─ Unit Tests
    └─ Build
    ↓
Code Quality Workflow
    ├─ SonarQube Analysis
    ├─ Dependency Check
    └─ Security Scan
    ↓
Deploy Workflow (if main branch)
    ├─ Build Production
    ├─ Deploy to Vercel
    └─ Create Release

⚙️ Workflows

1. Lint & Test Workflow

▼

Trigger: On every push and pull request

Duration: ~5-10 minutes

Jobs:

  • ESLint - Code style checking
  • TypeScript - Type checking
  • Prettier - Code formatting
  • Unit Tests - Test coverage
  • Build - Production build
  • Security Scan - Vulnerability detection

Configuration:

name: Lint & Test
on: [push, pull_request]
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
      - run: npm install
      - run: npm run lint
      - run: npm run type-check
      - run: npm run test
      - run: npm run build
✅ Success: All checks pass before merging to main

2. Deploy Workflow

▼

Trigger: On push to main branch only

Duration: ~3-5 minutes

Steps:

  1. Build production bundle
  2. Deploy to Vercel
  3. Create GitHub Release
  4. Send Slack notification

Configuration:

name: Deploy
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - run: npm run build
      - uses: amondnet/vercel-action@v20
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
⚠️ Warning: Requires Vercel token in GitHub Secrets

🔧 Setup Instructions

Step 1: Configure GitHub Secrets

Go to Settings → Secrets and add:

VERCEL_TOKEN          # Vercel deployment token
SONARQUBE_TOKEN       # SonarQube analysis token
SLACK_WEBHOOK_URL     # Slack notification webhook
NPM_TOKEN             # NPM registry token (optional)

Step 2: Enable Branch Protection

Require status checks to pass before merging
Require code reviews before merging
Dismiss stale pull request approvals
Require branches to be up to date before merging

Step 3: Configure Workflows

Edit workflow files in .github/workflows/:

  • lint-and-test.yml - Linting and testing
  • deploy.yml - Deployment
  • code-quality.yml - Code quality checks
  • pr-checks.yml - PR validation
  • release.yml - Release management

Notifications

Receive email notifications for workflow failures and successes.

Configure in: Settings → Notifications → Email

Get real-time Slack notifications for CI/CD events.

- name: Slack Notification
  uses: slackapi/slack-github-action@v1
  with:
    webhook-url: ${{ secrets.SLACK_WEBHOOK_URL }}

Send workflow events to custom webhooks.

Configure in: Settings → Webhooks

🔍 Troubleshooting

Common Issues

❌ Workflow Failed: "npm: command not found"

▼

Solution: Add setup-node action before npm commands

- uses: actions/setup-node@v3
  with:
    node-version: '18'

❌ Workflow Failed: "Permission denied"

▼

Solution: Check GitHub token permissions

  1. Go to Settings → Developer settings → Personal access tokens
  2. Verify token has required scopes: repo, workflow
  3. Regenerate token if needed

❌ Tests Failing Locally but Passing in CI

▼

Solution: Check environment differences

  • Verify Node.js version matches
  • Check for environment variables
  • Clear node_modules and reinstall
  • Check for timing-dependent tests

❌ Deployment Failed: "Vercel token invalid"

▼

Solution: Update Vercel token

  1. Go to Vercel dashboard → Settings → Tokens
  2. Create new token
  3. Update GitHub secret: VERCEL_TOKEN

⭐ Best Practices

1. Keep Workflows Simple

✅ Do: Break complex workflows into smaller, focused jobs
❌ Don't: Create monolithic workflows with too many steps

2. Use Caching

- uses: actions/cache@v3
  with:
    path: ~/.npm
    key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
    restore-keys: |
      ${{ runner.os }}-node-

3. Secure Secrets

  • Never commit secrets to repository
  • Use GitHub Secrets for sensitive data
  • Rotate tokens regularly
  • Use environment-specific secrets

4. Monitor Workflow Performance

  • Track workflow duration trends
  • Optimize slow steps
  • Use parallel jobs when possible
  • Cache dependencies

5. Document Everything

  • Add comments to workflow files
  • Document required secrets
  • Keep README updated
  • Create troubleshooting guide
